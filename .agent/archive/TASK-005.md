# TASK-005 보호탭(시크릿 탭)

- 상태: COMPLETED (2026-11-12)
- 요청: "보호탭 기능 추가해줘" → "보호탭은 시크릿 탭이야"

## 요구사항

1. 파일 › 새 시크릿 탭(⇧⌘N)으로 시크릿 탭을 연다.
2. 시크릿 탭마다 따로 메모리에만 있는 데이터 저장소(`WKWebsiteDataStore.nonPersistent()`)를 쓴다. 쿠키·캐시·로컬 저장소가 디스크에 남지 않고, 일반 탭이나 다른 시크릿 탭과 섞이지 않는다.
3. 일시 중단돼도 그 탭의 저장소는 유지(로그인 유지), 탭을 닫으면 저장소를 버린다.
4. 시크릿 탭에서 연 새 창(window.open)·⌘클릭 탭도 시크릿이며 같은 저장소를 쓴다(로그인 흐름 유지).
5. 세션 복원 파일에 저장하지 않고, 닫은 탭 다시 열기(⇧⌘T) 목록에도 넣지 않는다.
6. 시크릿 탭에서는 계정 저장을 묻지 않는다(채우기는 요청 시 가능).
7. 탭 바와 빈 페이지에서 시크릿 탭임이 보인다.

## 완료 조건 (Acceptance Criteria)

- [x] AC1. 시크릿 탭의 웹뷰는 영구 저장소가 아니고, 일반 탭은 기본 저장소다. 시크릿 탭끼리 저장소가 다르다.
- [x] AC2. 실제 쿠키로 격리 확인: 시크릿 저장소에 넣은 쿠키가 기본 저장소와 다른 시크릿 저장소에 보이지 않는다(기본 저장소는 읽기만).
- [x] AC3. 일시 중단 후 깨워도 같은 저장소, 팝업·백그라운드 탭이 시크릿과 저장소를 물려받는다.
- [x] AC4. 세션 저장 항목과 닫은 탭 목록에서 시크릿 탭이 빠진다. 계정 저장 질문이 시크릿 탭에서는 막힌다.
- [x] AC5. 메뉴 ⇧⌘N 연결.
- [x] AC6. 새 테스트는 일부러 깨뜨리면 실패(저장소 공유, 세션 저장, 닫은 탭, 상속, 계정 질문, 메뉴) — 확인 후 되돌림.
- [x] AC7. auto-fix-loop 통과, README 반영.
